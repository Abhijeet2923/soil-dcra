Sub-Task 1 — Backend Additions & Bug Fixes IN PROGRESS

This sub-task is the only one that touches Python. All changes are read-only additions or bug fixes. No existing endpoint, calculation, schema, or business logic was modified.

1a. New endpoints added ✅

app/api/v1/fields.py — 2 new endpoints appended NEW
✅
GET /api/v1/fields — returns all registered fields ordered by most recent
Used by React's "Select existing field" panel so returning users can pick their field without re-clicking the map. Calls existing _field_to_read() helper already in the file.
✅
GET /api/v1/problem-types — returns the 15-entry PROBLEM_TYPES list
Streamlit imported this directly from Python (from app.data.crop_data import PROBLEM_TYPES). React cannot do that — it needs an HTTP endpoint. This wrapper exposes the same data over the API with zero logic change.
app/api/v1/analysis.py — 2 new endpoints + 1 new import NEW
✅
GET /api/v1/crops/{crop_id}/economics?area_ha=X
Delegates entirely to economics_service.calculate_economics(crop, area_ha) which already existed but was never exposed as an endpoint. Returns: crop name, yield, price, revenue/ha, 7-item cost breakdown, total cost/ha, net margin/ha, total revenue, total cost, total margin, ROI%, disclaimer.
✅
GET /api/v1/crops/{crop_id}/sensitivity?area_ha=X
Delegates entirely to economics_service.calculate_sensitivity(crop, area_ha). Returns 3 scenarios: Conservative (75% yield, 85% price), Expected (100%/100%), Favorable (120% yield, 110% price). Each with revenue, profit, ROI. Streamlit re-implemented this logic inline — now React can call the authoritative backend function instead.
✅
from app.services import economics_service added to imports
The module existed; it just wasn't imported in analysis.py. Import pattern matches the existing soil_service, degradation_service, suitability_service imports in that same file.
app/api/v1/optimization.py — 1 new endpoint NEW
✅
GET /api/v1/fields/{field_id}/optimization-runs
Returns a list of all past CP-SAT optimization runs for a field (most recent first), with run_id, horizon, objective, status, and created_at. Enables a React history view so farmers can review previous rotation plans without re-running the optimizer.

1b. Bug fixes ✅

tests/smoke_test.py — 2 field naming bugs fixed + 3 new endpoint checks added FIXED
✅
Bug 1 fixed: find-or-create call changed from "lat": 17.385, "lng": 78.487 to "latitude": 17.385, "longitude": 78.487
The FieldCreate Pydantic schema (used by the router) uses latitude/longitude. The old smoke test was posting the wrong keys — Pydantic was silently ignoring them and storing null coordinates. This would have broken the React map integration immediately.
✅
Bug 2 fixed: Problems POST changed from "problem_type": "waterlogging" to "problem_code": "excess_water"
The FieldProblem model column is problem_code, not problem_type. The old smoke test was posting an unknown key — the problem was being stored with a null code. Also updated the print statement to use p['problem_code'].
✅
3 new smoke test checks added (steps 13, 14, 15)
Step 13: GET /fields/{id}/optimization-runs — asserts ≥1 run after optimize step
Step 14: GET /crops/{id}/economics — asserts net_margin_rs_ha present
Step 15: GET /crops/{id}/sensitivity — asserts all 3 scenario keys present
✅
Steps 3b and 3c added
Step 3b: GET /problem-types — asserts ≥10 entries
Step 3c: GET /fields — prints current field count
app/schemas/field.py — deleted FIXED
✅
Dead file removed. app/schemas/field.py defined FieldCreate and FieldRead classes that were never imported anywhere in the codebase.
A grep confirmed zero imports before deletion. The actual schemas in use are the inline Pydantic models defined directly inside app/api/v1/fields.py. Keeping the dead file caused confusion about which schema was authoritative.
